# Scientific figure workorder

Read /input/case.json, task.md, available files and environment/resources.yaml. Work in /app/work. Deliver under /app/output. Run helpers relative to /skills/weekly-skill. Start with the actual workorder and its output_contract. Inspect the supplied files even when filenames suggest a familiar paper. Examples are independent teaching data.

1. Inventory the inputs, original filenames and SHA-256. Open the actual table, SVG or PDF. For a PDF use pdftotext -layout plus a rendered page for tables, symbols and scale factors; cite page, panel and row. For XLSX use scripts/xlsx_table.py BOOK SHEET A1:G22 work/table.csv. It emits a cell-address map. Retain the original lookup for every normalized column or reshaped row. For CSV retain exact source row/field and hash. Record units, superscripts, case-sensitive entity names, time, group order, sample size, supplied bounds and any exclusions. When numeric values are unavailable, retain the original graphic, flag estimates explicitly and report the missing evidence.
2. Decide whether this is creation, editing an existing source, or both. For a source-preserving edit, inventory the **original** with `python scripts/local_edit.py supplied.svg`. Make a plan based on its actual element IDs or positional paths, state expected old value, new value, source locator and reason. Run `python scripts/local_edit.py supplied.svg plan.json /app/work/edited`. Copy original, edit plan, layered edited SVG and previews to output. Verify the requested change is visibly applied, including CSS precedence, and unrelated elements retain their geometry and text. For a Matplotlib-authored drawing identify the leaf path/use/style or leaf text, not the outer series group. Multi-part tasks require delivering both revised source and requested new chart. For PPTX/XLSX edit the actual chart/slide/worksheet and linked data in a working copy using installed tools; render with LibreOffice if available and verify slide/object order and unmodified components. Keep the native file.
3. For a numeric plot write a small JSON spec using the **case data**. See README and examples/assay.json. Run `python scripts/figure.py /app/work/spec.json /app/work/render1`. SVG remains editable, and the copied CSV + JSON regenerate the figure. Preserve field semantics: distinguish a SD, SE, confidence interval and range; absolute interval endpoints go into bounds. Convert symmetric magnitudes to explicit endpoints in a separately recorded transform. Keep missing cells missing. Never silently aggregate replicates or invent stars, sample sizes, molecular relations or zero values. Obtain entity spellings and legend order from the actual source. Use one unit convention per axis. Read back a minimum, maximum, outlier, one uncertainty interval, and one value from every series. Check a scientific conclusion directly against source values. If asked for a schematic use the evidence workflow in references/schematic.md.
4. For restyling change only requested spec fields, append a changes entry (before/after, source, reason) and rerender in a fresh directory. Retain both revisions and compare source hashes, mark-to-row links and numerical encodings. For a scientific-data correction, patch the specified source value in a derived file, documenting the original cell and downstream marks; never mutate the input. If the requested chart is beyond the bundled grammar, use the native plotting library, attach stable SVG IDs, build the same reverse index, and adapt the checks to that geometry. Budgets favor a complete basic case before adding decoration.
5. Open real previews at final size. Run `python scripts/verify.py /app/work/render1` for quantitative outputs. Inspect axes, units, color/shape correspondence, text overlap, clipped intervals, panel alignment, outliers and zoomed vector text. Inspect scientific entities, spatial/edge direction, data encoding, labels, editable source and export independently. Mark inapplicable checks with a reason. If error_label or n is absent in the materials, mark it unknown. For figures with supplied references compare scale, direction, row counts, series, outliers and labels with the actual reference; report any intentional changes. Check specific journal dimensions/DPI, transparency, RGB/CMYK/ICC and font requirements when provided. Record color space honestly; a four-channel RGBA PNG is RGB plus alpha.
6. Copy actual deliverables with task-required names to /app/output. Write preliminary result.json early, then finalize **every field of the original output_contract** using actual evidence. `python scripts/finish_case.py /input/case.json /app/work/actual.json /app/output/result.json` preserves existing diagnostics and enforces top-level required field presence. Inspect nested fields and types separately. Include original case_id, status, artifacts with relative paths, source locations, changes, uncertainties, checks and any human confirmations actually received. Where input is missing, identify which item; where evidence is inconclusive, state which conclusion is uncertain; where tooling fails, retain partial artifacts and the error. A successful subprocess alone does not establish scientific correctness.

For repeated cases never use a demonstration chart as a case answer. Each output directory is immutable by convention; render into a new revision and publish the verified files.
