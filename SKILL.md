# Produce or revise a source-grounded figure

1. Read `/input/task.md`, `/input/case.json`, every required attachment, and the actual case `output_contract`. Resolve attachment paths before interpreting the task. Check which panels must be created or edited, what stays fixed, required exports and dimensions, which sources are allowed, and what the result fields mean. Prefer supplied primary evidence. Read original figures and captions as well as extracted PDF text. For a numeric plot, use the supplied source data with its actual groups, units, and missing-value conventions. Do not infer data from the workorder name. Review `environment/resources.yaml` for the available render and extraction tools.
2. Write a short inventory in `/app/work`: target panel, entities, directional relationships, source locations, explicitly requested edits, and remaining uncertainty. Use a figure/panel, page/table, local row/key, or other reproducible locator for each claim. Distinguish gene, protein, family, subunit, and complex. Keep species, condition, cell type, and molecular state attached to the assertion they qualify. Do not promote an association, an observed correlation, or a proposed mechanism to a direct causal arrow. Limit use to non-dual-use biology and ordinary data visualization.
3. Produce the actual editable artifact. For a diagram from scratch, use `scripts/pathway.py draw` with the input described in `README.md`. Give the main sequence aligned slots, separate competing branches into rows, and anchor receptors at the correct membrane. Use the source's labels and relationship vocabulary. For an existing SVG, use `edit` for label and style updates after resolving the stable IDs and reading their current values. For unsupported edits or other vector formats, modify the supplied editable source with its native tools and verify untouched objects with a source-to-result diff. Keep the source and the rendered exports synchronized. For requested numerical panels, use editable SVG from an available plotting tool, such as Matplotlib with `svg.fonttype='none'`, and export real PNG/PDF from the same plotting specification. Retain source data alignment, denominators, scales, uncertainty definition, and units.
4. Save partial progress under `/app/output` early. For a straightforward case, run `python3 /skills/weekly-skill/scripts/pathway.py draw /app/work/graph.json --case /input/case.json --output /app/output`. In edit mode, supply `--source` and an edit plan JSON. `--case-fields` can include additional actual result fields. Reconcile `result.json` with the original contract after the last export. Preserve the original `case_id` and field names and types. If the contract prescribes a different representation or artifact name, adapt to it and recheck references. Keep temporary work out of the final output directory. Record real file paths, dimensions, export checks, source locations, changes, and uncertainty. Be explicit about partial outcomes and failed outputs.
5. Inspect the actual previews at full size and at intended presentation size. Check all nodes, legends and labels, compare arrows and numerical encodings to the evidence, and verify the source can still be edited. Reposition collisions, preserve original components outside any requested edit, and rerender. Save a compact evidence and verification record. Check file signatures, result schema, artifact hashes, and any requested before/after comparison. Treat consistency checks as structural evidence and use input materials for scientific review. Report only measured runtime or comparison values if the case asks for them.

Use `scripts/pathway.py chart` with a chart specification and `--source` for a supplied CSV. For multiple panels, render into separate work directories, assemble the required editable results, and link their corresponding source records from the final result. A standard-library Python 3.10+ environment can generate and edit SVG. Previews can use installed Inkscape, CairoSVG, librsvg, Chromium, or Matplotlib for this package's SVG subset. If shell export is unavailable, render the saved SVG with the platform browser or document tool, verify the actual files, and report which renderer ran. Never substitute material from `examples/` for case inputs.
